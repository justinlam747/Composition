Phone camera setup

  1. On Mac or Windows, stop the existing development server and run npm run dev:phone from the project folder. Open the editor in Chrome or Edge.
  2. On a Mac, open ios/CompositionCamera.xcodeproj in Xcode. Select your signing team and a unique bundle identifier. Connect a compatible iPhone running iOS 17 or later, enable Developer Mode if requested, and build and run on that phone.
  3. Connect the phone and computer to the same trusted Wi-Fi network. Allow Node.js on private networks if Windows Firewall asks. The tracking bridge needs inbound TCP port 3003; WebRTC also needs direct local UDP connectivity.
  4. Open Phone camera → Pair iPhone in the editor. Tap Scan pairing code inside the iPhone companion and scan the desktop QR to connect automatically. If multiple addresses appear, choose the reachable one under Connection address before scanning. Allow Camera and Local Network access. Enter manually remains available as a fallback.
  5. Hold the phone in landscape. Frame a starting shot in the editor and choose Set starting pose. The phone shows the virtual shot returned by the desktop. Adjust Movement from 1× to 10×; the default 5× maps 20 cm of phone movement to one scene meter without changing rotation. Move the phone to test the framing, then choose the red Record button.
  6. Use Pause to hold the view while repositioning your phone, then Resume to continue without jumping. Paused time is excluded from a recorded take. Movement sensitivity is locked during recording.
  7. Choose Stop & save. Open Animate to replay the camera block, stretch it to change speed, split it, or edit its keys. The take stops at the next camera block or scene end.

This companion captures six-axis motion, not video. The phone's camera images stay on the phone. The returned preview is the rendered virtual scene, not an overlay on a real camera feed. Tracking loss or hiding the editor stops the take and saves the captured portion. Set the starting pose again before another take.

The connection uses a temporary pairing code over your local network. Keep it on trusted Wi-Fi; the bridge is not intended for public hosting. The AI and file APIs remain bound to localhost.

The QR is generated locally and expires after ten minutes unused. Choose New pairing code to refresh it and revoke the old session. Scan from inside Composition Camera, not the system Camera app. QR pairing avoids typing but still needs a working Wi-Fi or USB network; it does not repair a failed connection.

Statistics are hidden by default. To compare preview latency, enable three-dot menu → Debug information on the phone and editor. Start with JPEG baseline, run 20 latency pulses on the phone, and export the results on the Mac. Switch to WebRTC and repeat at 60 and 30 fps. The pulse numbers estimate control-to-decoded-frame delay, not physical motion-to-screen latency. Keep the editor tab visible and export before switching modes.

The native iPhone project compiles for iPhoneOS. Install it with Xcode and resolve any developer-trust prompt on the phone before testing; a simulator cannot validate ARKit hardware tracking or device latency.
