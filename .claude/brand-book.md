# composition

A mobile-first videography editor. Use the user's direction: a white theme, rounded corners, one font and minimal persistent controls.

- Typography: Manrope only. Timecodes use tabular numbers in the same font. No separate monospace font.
- Project home: use a full-height white sidebar with the brand, New project, All projects / Recent / Animated collections, title-only project quicklinks and local storage status. The content area has a breadcrumb, title, search/sort toolbar, and a grid of actual first-frame scene images with names and dates below. Two columns by default, three above 1600px; below 700px, use a 68px icon sidebar and one column. Preview images use the saved camera when present, otherwise frame all visible objects. Cards lift and gently zoom images on hover, with staggered entrances and smooth easing; all motion is gated by prefers-reduced-motion. Do not add a home footer, total-count label, workspace tagline, or resume-copy block. Sidebar quicklinks show only project titles, with the current browser draft first. Use a custom rounded sort menu with neutral keyboard focus. Each card has a three-dot menu with Output and Delete; Output loads that project directly, and Delete uses a confirmation dialog. Project naming uses a native modal dialog. The editor brand returns home and saves; the adjacent Save icon stays visible. Keep the project name in the scene menu to preserve canvas space.
- Color: white panels, warm near-white canvas, graphite text and subtle orange editing accents. Interface colors use the semantic oklch tokens in src/styles.css.
- Layout: prioritize the scene. The composition name and icon float directly over the canvas without a background pill. Use a compact 16px name and 32px header icons. No project-name field or reserved header row. Empty header space passes pointer input to the scene. Objects, Scene and Animate are icon buttons at the top left, beside the name on desktop and below it on mobile. Use accessible names, tooltips and visible pressed states. There is no bottom dock.
- Selection: clicking a body part opens a floating pose island and transform tools. Clicking empty space or closing the island dismisses them. No dedicated Pose mode, sidebar or reserved canvas space, including on mobile.
- Pose: joint selection, transform values, current time and an add/update key action in the island. Gizmos scale to the selected part, with a minimum touch size. No bone counts, parent information or help copy.
- Animate: the object/camera timeline floats over the composition and starts at 220px. Opening, resizing or minimizing it must never resize the canvas or alter the camera frame. Drag its top divider or use the focused divider's Up/Down arrows to resize it between 180px and half the workspace height. Minimize it to a 36px playback strip; expanding restores its size and editing context. Tracks scroll independently inside the panel. Camera has position and rotation only; lens controls are intentionally absent.
- Menus: Demo mode is a switch inside the three-dot menu, not a header button. Turning it off preserves the current scene and keys. Scene files, grid/skeleton visibility, clear/remove and help also live in this menu.
- Shape: 12px controls, 18-22px panels, generous touch targets. Use Lucide icons.
- Dropdowns and focus: all selects use white rounded controls and matching 12px popup menus, soft gray hover/selection, Manrope and subtle gray borders. Use native customizable-select styling where supported, with native select fallback. Keyboard focus and selection outlines are neutral gray (`--focus`), never orange. Keep 24px between floating tools and the timeline, plus 9px vertical toolbar padding and a 6px gap before its tracks.
- Content: no marketing cards, phase labels or future-feature notices on the main screen. Demo animation is still labeled as prepared data in its notification.
- Motion: only short reduced-motion-aware panel entrances. Character animation remains user controlled.
- Compatibility: existing scene JSON and local storage keys remain unchanged when renaming the interface.
- Timeline modes: one compact mode menu offers Keyframes, Value graph and Velocity. Value graph uses the same ruler/playhead, a blue property curve (`--blue`), and yellow horizontal handles (`--graph-handle`). Outlined handles are not yet applied; dragging them sets a flat endpoint tangent. Property/axis selectors stay above the graph; exact Time/Value fields appear below on selection. Opening Value graph gives the floating panel at least 300px where space permits, then it remains resizable. Plot scene units, degrees or scale factors, never substitute speed for property value. No presets.
- Velocity timeline: reuse the timeline ruler, playhead and transport with one Velocity lane. Keys independently store time and relative speed for the entire selected object or animation block. Drag horizontally to retime and vertically to change speed; exact Time and Speed fields appear on selection. Add at the playhead, delete and undo like ordinary keys. Relative speeds redistribute motion within the existing duration; all-zero keys pause it.
- Objects: the top-left Objects icon opens an object list/library. Details extend the floating inspector with dimensions, reference images and saving; collapse these details by default.
- Optional panels: 300px wide beside the canvas on desktop, 280px on medium screens. Below 700px, use a rounded bottom sheet anchored to the bottom edge, max 55dvh tall, with its own scroll area, sticky heading and safe-area padding. Manual controls remain floating.
- AI: Object, Composition and Movement tabs; Live and prepared Demo choices are explicit. Preview suggestions before application with a small orange canvas badge.
- Output: a visible text **Output** button opens the separate `#output` page. Use three compact steps: Preview, Direction, Generate. Match the editor's warm white, graphite, subtle borders and small controls; output has no orange accents. Omit hero copy and repeated step labels. Keep a large preview beside the active step on desktop; stack preview and controls below 700px. Use locally bundled monochrome Gemini, fal and ByteDance marks to identify services. Gemini image generation lives in Direction, with thumbnail downloads and explicit Use for video checkboxes; video references are limited to nine. Show concise prerequisites beside blocked actions and a persistent Back to editor button. Keep the editor renderer mounted but hidden/inert to preserve framing; its global shortcuts must be suspended. No grid, controls or selection cues enter the guide.
- Camera / AR: a compact panel above the camera switch owns camera selection and support messages. Closing it keeps a visible stop-camera badge. Room placement uses a separate full-screen overlay with surface instructions and touch controls; the editor is inert until exit. Camera overlay and room tracking are named explicitly.
- Scene camera: one selectable camera object, a fixed 16:9 gate with a neutral gray border and dimmed exterior, and simple Move/Rotate controls. Camera view and editor Orbit view are independent. The saved scene camera supplies guide framing whenever present.
- Phone camera: a phone icon opens the optional pairing/capture panel. Show the computer address, pairing code, tracking state and starting-pose/record controls. During phone control the scene editor is inert while capture controls remain available. Saved takes use ordinary camera animation blocks. The phone monitor displays the virtual shot; camera imagery stays on the phone.
- Animation blocks: show named action blocks on one row per object. Drag the body to move; drag an edge to stretch playback; Split cuts at the playhead. Double-click or Edit keyframes opens an isolated, scrollable keyframe view with an All blocks breadcrumb. The folder button at the top right opens Animations in the optional right sidebar (a bottom sheet on mobile) and reveals the timeline. Cached animation cards stack vertically, with prepared examples labeled explicitly. Copies on the timeline are independent of the cached source. Keep the canvas free of a persistent Demo scene badge; demo status remains in the scene menu and notifications.
- Output prompt assistance: place a compact Optimize action inside the Video direction and Visual baseline text areas. Apply the result directly in the same field and relabel the action Reoptimize after the first result. Show source first/last thumbnails together and generate matched endpoint pairs. Gallery images have download/remove controls; the reference strip has independent deselection. Uploads always guide image generation, independently of video selection. Use one Generate images button to add another matched pair after prompt optimization; omit image-count selects and application gallery caps. The nine-reference limit applies only to video. Keep these controls neutral and usable on mobile.
